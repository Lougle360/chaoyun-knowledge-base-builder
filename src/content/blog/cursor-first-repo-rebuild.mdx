旧仓库里堆的是 Markdown 技能说明与脚本，并不是网站。这次目标很明确：把它改造成「超云的Ai之旅」博客，本地能 `dev`，文章用 MDX 管理。

## 先定边界

动手前先和 Cursor 对齐三件事：

1. **产品形态**：内容站，不是应用后台。
2. **技术栈**：Astro + MDX，中文界面。
3. **内容主线**：Cursor / Codex 实操与项目复盘。

边界清楚后，Agent 才不会把旧技能文档「优化」成半吊子产品页。

## 推荐的协作节奏

- 先让 Agent **读上下文与偏好**，再改代码。
- 一次只推一个里程碑：脚手架 → 布局 → 示例文 → README。
- 每个里程碑后本地起服看一眼，再继续。

```bash
npm install
npm run dev
```

## 我带走的 checklist

- 首页品牌名要是 hero 级信号，而不是藏在导航里。
- 文章列表与详情共用同一套内容集合，避免双写。
- README 用中文写清安装与启动，方便下次自己回来续写。

如果你也在把「文档型仓库」迁成站点，可以把旧内容先移出主路径，先让博客可读可跑，再决定哪些资料值得回流。
